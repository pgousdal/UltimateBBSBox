# M8.4 acceptance review

The original M8.4 criteria are covered by the following implementation and
tests. Monitoring remains derived and read-only; no remote control or
notification service is part of this milestone.

| Criteria | Result | Evidence |
|---|---|---|
| 1–6 health/host/observation model | PASS | `ubb_observatory.models`, `test_health_lifecycle_and_unknown_host`, heartbeat tests |
| 7–14 alert lifecycle, identity, recurrence, escalation/history | PASS | `ubb_monitoring.engine`, `test_dedup_clear_recurrence_and_bounded_history` |
| 15–20 service/readiness/schedule health | PASS | collector health derivation and supervisor regression suite |
| 21–24 backup/preservation/qualification semantics | PASS | collector alerts and M7/M8.3c regression tests |
| 25–28 storage, session safety, corruption/retention | PASS | storage/corruption tests and bounded JSON state |
| 29–34 CLI/dashboard/API observability | PASS | admin/dashboard tests, monitor CLI, `/api/v1/health`, host/alert APIs |
| 35–39 evaluator, timer, privilege, privacy | PASS | `ubb-monitor.py`, systemd units, compile/security tests |
| 40–45 no RPC/notifications/database/products/M6 | PASS | scope review and dependency-free implementation |
| 46–49 M8.1–M8.3 and M0–M7 compatibility | PASS | full regression suite |
| 50 validation | PASS | `make check`, compileall, diff check |
| 51 documentation | PASS | `docs/MONITORING.md` and this review |

Heartbeat input is strict and local-file based. Remote hosts with no or stale
telemetry remain `UNKNOWN`; timestamps, host IDs, and metric names are bounded.
Storage observations use both free percentage and absolute free-byte thresholds.
