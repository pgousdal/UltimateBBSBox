# M6.6 FTN transport/core

M6.6 models a Debian-package BinkD mailer with a Husky-compatible tosser/scanner
strategy. UBB does not implement BinkP, packet parsing, or a tosser in Python.
The reference transport is TCP/24554 and public listening is opt-in with
explicit peers; the private home host can remain behind the M6.2 overlay.

Networks are independent and use strict `zone:net/node[.point]` addresses,
multiple AKAs, uplinks, nodelist references, area tags, spool roots, encoding,
and allow-listed archive methods. Netmail and echomail are distinct. Generic
adapters represent import/export, native FTN, batch, and scheduled exchange;
M3 supplies schedules/holds. Adapter-owned MSGID/checkpoint/SEEN-BY/PATH state
prevents duplicate imports and loops. Character encoding is explicit and is not
assumed to be UTF-8.

Inbound/outbound/temp/bad/duplicate spool directories are mutable living state,
not M1 preservation artifacts. Active spool backup requires a tool-consistent
strategy; raw live-directory tar is not claimed safe. Recovery combines package
and configuration, external secrets, checkpoints/nodelists, spool strategy, and
BBS living-state backups. Diagnostics expose only queue counts/ages, peer/area
metadata, and aggregate failures—never message bodies or passwords.

Tier-1 FTN capability is not inferred from historical BBS participation; Mystic,
ABBS, and AmiExpress qualification remains `HUMAN_REQUIRED`. No real FTN peer
traffic is generated by tests. Use `python3 scripts/ubb-ftn.py {status,networks,
addresses,peers,areas,queues,mappings,validate,render}` for safe diagnostics.
