# M9.1d DOSEMU2 serial investigation

## Status: INCOMPLETE

The existing M9.1c COM1 failure remains preserved: both host-to-guest and
guest-to-host COM1 tests reported `Error reading from device COM1: Unknown error
code` with the DOSEMU2-created PTY and an external socat PTY pair. No CTTY result
is treated as UART proof.

The disposable qualification VM is reachable and was inspected without changing
production state:

* Debian GNU/Linux 13 (trixie), kernel `6.12.101+deb13-amd64`, x86_64;
* pinned DOSEMU2 2.0pre9 revision 7076 at the recorded `/opt` path;
* the preserved FreeDOS LiveCD mount is present;
* no physical serial device or public network was used.

An initial direct invocation exposed a packaging/runtime issue: the wrapper could
not load `libdosemu2.so`/FDPP libraries until the pinned `lib`, `lib/dosemu`, and
`lib/fdpp` directories were supplied through `LD_LIBRARY_PATH`. With those paths,
`dosemu --version` reports 2.0pre9 revision 7076, but this does not prove a guest
boot or serial operation. A minimal FreeDOS boot/BIOS INT 14h/UART reproducer and
PTY termios trace still need to be run in the VM.

Therefore no conclusion is yet justified among configuration error, FreeDOS/
FDPP interaction, PTY behavior, DOSEMU2 regression, or backend unsuitability.
The canonical backend remains `PARTIALLY_QUALIFIED`; M9.1a, M9.1b, M9.1c, and
M9.1d remain incomplete. No fallback emulator was substituted.
